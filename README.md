# Детекция трафика сервисов сбора данных

Задача: по событиям cookie за суточное окно оценить, принадлежит ли её трафик известным
сервисам автоматизированного сбора данных. Ответ - score от 0 до 1 на каждую cookie из test,
метрика - максимальная precision среди порогов, где recall не меньше 0.70; cookie с одинаковым
score отмечаются целиком. Разметка построена по источникам трафика, поэтому модель учится
отличать эти сервисы, а не любую автоматизацию

## Результат

| Модель | fold_a | fold_b | Среднее |
|---|---:|---:|---:|
| База quickstart: два счётчика, случайный лес | 0.1035 | 0.0954 | 0.0995 |
| Финал: 62 признака, усреднение трёх CatBoost | 0.7960 | 0.7131 | 0.7546 |

Оценка локальная: `fold_a` учится на 04-06..04-09 и проверяется на 04-10..04-12, `fold_b` на
04-06..04-12 и 04-13..04-16, доля ботов в проверке 0.0869 и 0.0773. По этим же дням выбирались
признаки и модель, поэтому на скрытой неделе результат может быть ниже

## Данные

В `bot_detection_challenge/data/` лежат `train.csv` (11 091 cookie с меткой, окна 04-06..04-19),
`test.csv` (4909 cookie, 04-20..04-26) и `events.csv.gz` (328 905 событий десяти типов, внутри
окон встречается девять). Рядом в `bot_detection_challenge/` лежат условие, метрика и
`sample_submission.csv`. У каждой cookie своё суточное окно, признаки считаются только по
событиям внутри него

В train 40 779 событий попали на конец окна или позже, в test таких событий нет. Внутри окон
4293 полных дубля, платформа записана 11 способами. События вне окна и дубли удалил, написания
платформы объединил. У ботов глубже выдача, больше локаций, выше пик событий за минуту и короче
интервалы. Подробности в `eda.ipynb`

## Признаки и модель

62 признака в десяти семействах: объём, состав действий, разнообразие и глубина выдачи, ритм,
возраст cookie, клиент, курсор, курсор на краю экрана, разброс курсора и география. Использовал
агрегаты событий внутри окна и метаданные cookie: `cookie_id` не признак, `item_id` и
`search_query` входят только в счётчики разнообразия, статистик по другим cookie нет. Сырая
строка User-Agent проверялась гипотезой и в финал не вошла

Финал - среднее вероятностей трёх `CatBoostClassifier` с seed 0, 17 и 42: глубина 6, 1500
итераций, learning rate 0.03, l2 10, CPU, четыре потока, без ранней остановки. Усреднил три
модели, чтобы уменьшить зависимость от seed. Обучение трёх моделей на полном train занимает
около 20 секунд, весь `solution.ipynb` около 30 секунд при пике памяти 740 МБ

## Эксперименты

В `experiments.ipynb` сравнил базу и 15 гипотез. Оставлял вариант, если средняя метрика росла и
ни одно разбиение не ухудшалось. Смесь с HistGradientBoosting дала лучшее среднее, 0.7653, но
снизила `fold_a` с 0.7960 до 0.7740, поэтому в итоговую модель не вошла. Прогоны записаны в
MLflow, результаты - в `results/experiments.csv`, прежние опыты - в `results/history.csv`

## Файлы

- `scripts.py` - чтение данных, окно, признаки, метрика, разбиения и сборка финальной модели
- `tracking.py` - запись прогонов в локальный MLflow
- `test_scripts.py` - тесты метрики, разбиений и границ окна
- `eda.ipynb` - разведочный анализ и таблица решений
- `experiments.ipynb` - база, гипотезы, срезы и итог
- `solution.ipynb` - обучение итоговой модели и запись `submission.csv`
- `results/` - журнал прогонов и история прежних экспериментов

## Воспроизведение

Python 3.12, зависимости с зафиксированными версиями в `requirements.txt`: numpy, pandas,
scikit-learn, CatBoost, matplotlib, MLflow, nbconvert, ipykernel

```
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest test_scripts
```

Ноутбуки выполняются сверху вниз в чистом ядре. `eda.ipynb` и `solution.ipynb` работают сами по
себе, `experiments.ipynb` создаёт локальное хранилище MLflow в `.mlflow` и обучает все показанные
варианты, это около десяти минут

```
.venv/bin/jupyter nbconvert --to notebook --execute --inplace solution.ipynb
```

Результат - `submission.csv` на 4909 строк в порядке `test.csv`, SHA-256 приложенного файла
`0e324c5b74349993aad18cd90a4d7254217a5309ce7f6d9238f1d6b9ff6b3fb6`. На этой машине повторный
запуск даёт тот же файл, в другой среде значения score могут отличаться. История прогонов
открывается интерфейсом MLflow

```
.venv/bin/mlflow ui --backend-store-uri sqlite:///.mlflow/mlflow.db --host 127.0.0.1 --port 5001
```
